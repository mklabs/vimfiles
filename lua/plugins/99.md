ThePrimeagen's **99** is a Neovim plugin designed for "skilled developers" who want to use AI without handing over full control. Unlike Cursor or Copilot which often try to write entire files, **99** focuses on small, scoped, and highly controlled interactions within your existing Neovim workflow.

The core philosophy is: **You provide the skeleton, AI fills the gaps.**

### 1. Prerequisites

Before using the plugin, you need one of the supported AI CLI backends installed on your system:

* **OpenCode** (Default & Recommended)
* **Claude Code** (`claude` CLI)
* **Cursor Agent**
* **Gemini CLI**

### 2. Installation (Lazy.nvim)

Add this to your plugin list. Note that you must call the `setup` function for the plugin to initialize properly.

```lua
{
    "ThePrimeagen/99",
    dependencies = { "nvim-lua/plenary.nvim" },
    config = function()
        local _99 = require("99")
        _99.setup({
            -- OpenCode is default; you can switch to ClaudeCodeProvider, etc.
            provider = _99.Providers.OpenCodeProvider,
            
            -- Project-specific AI instructions
            md_files = { "AGENT.md" }, 
            
            -- Optional: configure where to look for global "skills"
            custom_rules = { "~/path/to/my/rules/" },
        })

        -- Keymaps
        vim.keymap.set("v", "<leader>9v", function() _99.visual() end, { desc = "99 Visual" })
        vim.keymap.set("n", "<leader>9s", function() _99.search() end, { desc = "99 Search" })
        vim.keymap.set("n", "<leader>9x", function() _99.stop_all_requests() end, { desc = "99 Stop" })
    end
}

```

### 3. Core Features & Usage

#### A. Scoped Editing (`visual`)

Highlight a block of code (like an empty function or a messy loop) and trigger the visual command.

1. Enter Visual Mode and select code.
2. Press your keymap (e.g., `<leader>9v`).
3. A prompt will appear. Type what you want (e.g., `"Implement this using a hashmap for O(1) lookups"`).
4. The AI will process the request and replace your selection with the result.

#### B. Project Search (`search`)

This is the direction the plugin is heading—using AI as a high-powered search and "work" agent.

* Trigger `search()`.
* Input a prompt like `"Find all places where we handle user authentication and list the edge cases we missed."`
* The results are populated into your **Quickfix list**, allowing you to jump directly to the relevant files.

#### C. Context References (`@` and `#`)

When typing a prompt in the 99 input box, you can inject context dynamically:

* **`@filename`**: Fuzzy search and attach a specific file from your project to the prompt.
* **`#rule`**: Reference specific "rules" or "skills" defined in your `AGENT.md` or custom rule directories.

### 4. Setting up Project Context (`AGENT.md`)

The plugin automatically looks for an `AGENT.md` file in your project root (or as configured in `md_files`). This file should contain:

* Coding standards (e.g., "Always use functional patterns").
* Architecture notes (e.g., "This project uses a Clean Architecture with a repository pattern").
* Specific "Skills" the AI should know when working on this repo.

### 5. Troubleshooting

* **Permissions**: If using OpenCode, you might need to set an environment variable to allow it to edit files: `export OPENCODE_PERMISSION='{"edit": "allow"}'`.
* **Logs**: If something goes wrong, you can use `require("99").view_logs()` to see exactly what was sent to the AI and what it returned.

**Summary of Workflow:**

1. **Define** the structure of your code.
2. **Select** the area you want the AI to work on.
3. **Prompt** with specific context using `@` for files.
4. **Verify** the small, manageable change the AI made.
